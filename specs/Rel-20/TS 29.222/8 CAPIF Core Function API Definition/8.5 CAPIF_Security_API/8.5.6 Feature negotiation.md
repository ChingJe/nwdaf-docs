# 8.5.6 Feature negotiation

General feature negotiation procedures are defined in clause 7.8. Table 8.5.6-1 lists the supported features for CAPIF_Security_API.

Table 8.5.6-1: Supported Features

<table>
<colgroup>
<col style="width: 15%" />
<col style="width: 24%" />
<col style="width: 59%" />
</colgroup>
<thead>
<tr class="header">
<th>Feature number</th>
<th>Feature Name</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr class="odd">
<td>1</td>
<td>Notification_test_event</td>
<td>Testing of notification connection is supported according to clause 7.6.</td>
</tr>
<tr class="even">
<td>2</td>
<td>Notification_websocket</td>
<td>The delivery of notifications over Websocket is supported according to clause 7.6. This feature requires that the Notification_test_event feature is also supported.</td>
</tr>
<tr class="odd">
<td>3</td>
<td>SecurityInfoPerAPI</td>
<td>Indicates the support of negotiating and obtaining service API security method information per API.</td>
</tr>
<tr class="even">
<td>4</td>
<td>RNAA</td>
<td><p>Indicates the support of the RNAA functionality.</p>
<p>This feature enables the following functionalities:</p>
<p>- Support the OAuth grant types for RNAA.</p>
<p>- Support to convey the authorization code in access token requests to support the "authorization code" grant type for RNAA.</p>
<p>- Support to communicate the resource owner ID for RNAA access token requests/responses.</p>
<p>- Support to communicate the new cause codes for AEF authorization revocation.</p></td>
</tr>
<tr class="odd">
<td>5</td>
<td>CAPIF_Ext1</td>
<td><p>Indicates the support of the enhancements for CAPIF functionality.</p>
<p>Within this feature, the following enhancements are covered:</p>
<p>- Support to communicate the concerned access token in the authorization revocation notification.</p>
<p>- Support finer-granularity API access control.</p></td>
</tr>
<tr class="even">
<td>6</td>
<td>CAPIF_Ext2</td>
<td><p>Indicates the first set of enhancements to support the Rel-19 enhancements to the CAPIF functionalities.</p>
<p>This feature enables the following functionalities:</p>
<p>- Support generic string-based OAuth scope encoding based on clause 3.3 of IETF RFC 6749 [23].</p></td>
</tr>
<tr class="odd">
<td>7</td>
<td>CAPIF_4</td>
<td><p>Indicates the second set of the enhancements to support the enhancements to the CAPIF functionalities.</p>
<p>Within this feature, the following enhancements are covered:</p>
<p>- Support to use the “AUTHORIZATION_ISSUE” cause for service API revocation.</p></td>
</tr>
