# 9.3.2.4 Location reporting trigger

Table 9.3.2.4-1 describes the information flow from the location management client or VAL server to the location management server for triggering a location reporting procedure.

Table 9.3.2.4-1: Location reporting trigger

<colgroup>
<col style="width: 33%" />
<col style="width: 16%" />
<col style="width: 50%" />
</colgroup>
<tbody>
<tr class="odd">
<td>Information element</td>
<td>Status</td>
<td>Description</td>
</tr>
<tr class="even">
<td>Requestor Identity</td>
<td><p>M</p>
<p>(see NOTE 1)</p></td>
<td>Identity of the requesting authorized VAL user or VAL UE or VAL server</td>
</tr>
<tr class="odd">
<td>Identity</td>
<td><p>M</p>
<p>(see NOTE 1)</p></td>
<td>Identity of the requested VAL user or VAL UE</td>
</tr>
<tr class="even">
<td>VAL service ID</td>
<td>O</td>
<td>Identity of the VAL service for which the location reporting trigger is set.</td>
</tr>
<tr class="odd">
<td>Immediate Report Indicator</td>
<td><p>O</p>
<p>(see NOTE 2)</p></td>
<td>Indicates whether an immediate location report is required</td>
</tr>
<tr class="even">
<td>Requested location information</td>
<td><p>O</p>
<p>(see NOTE 2)</p></td>
<td>Identifies what location information is requested(e.g., geographic area). This information element may be represented as VAL service area ID(s) when this information flow from VAL server to the location management server.</td>
</tr>
<tr class="odd">
<td>Triggering criteria</td>
<td><p>O</p>
<p>(see NOTE 2)</p></td>
<td>Identifies when the requesting client/VAL server is expecting to receive the location report from the requested VAL user/ VAL UE as specified in table 9.3.2.4-2.</td>
</tr>
<tr class="even">
<td>Minimum time between consecutive reports</td>
<td><p>O</p>
<p>(see NOTE 2)</p></td>
<td>Defaults to 0 if absent otherwise indicates the interval time between consecutive reports</td>
</tr>
<tr class="odd">
<td>Endpoint information</td>
<td>O</td>
<td>Information of the endpoint of the requesting VAL server to which the location report notification has to be sent. It is provided if Immediate Report Indicator is set to required.</td>
</tr>
<tr class="even">
<td>Adaptive reporting</td>
<td>O</td>
<td><p>It indicates the request for an adaptive location reporting by dynamically adjusting the configuration. Following are possible values:</p>
<p>- "DIRECT UPDATE", indicates the SEAL LMS to directly update the SEAL LM client once configuration is adjusted; or</p>
<p>- "SUGGESTIVE UPDATE", indicates that the VAL Server subscribes to receive the suggested configurations from the SEAL LMS. The related notifications shall be sent by SEAL LMS before updating to the SEAL LM client.</p></td>
</tr>
<tr class="odd">
<td>&gt; Energy saving indicator</td>
<td>O</td>
<td>It indicates the energy saving for the target VAL UE should be considered for SEAL LMS when it provides the adaptive location reporting configuration provisioning (e.g. decrease the reporting frequency when the target VAL UE’s energy consumption almost reaches its pre-defined daily maximum (NOTE 3)).</td>
</tr>
<tr class="even">
<td>&gt;Energy requirement</td>
<td>O</td>
<td>It indicates the energy consumption requirements for the SEAL LM client reporting and corresponding thresholds.</td>
</tr>
<tr class="odd">
<td colspan="3"><p>NOTE 1: The identity of the requesting VAL user/UE/VAL server and the requested VAL user/UE should belong to the same VAL service.</p>
<p>NOTE 2: At least one of these rows shall be present.</p>
<p>NOTE 3: The LMS may define the daily maximum of VAL UE energy consumption based on e.g. operators’ polices or pre-configuration.</p></td>
</tr>
</tbody>
</table>

<td>O</td>

<td><p>O</p>

</tr>
<tr class="even">
<td>Reporting schedule</td>
<td>O</td>

</tr>
