# 8.1.7 Feature negotiation

The optional features listed in table 8.1.7-1 are defined for the Eees_EASRegistration API. They shall be negotiated using the extensibility mechanism defined in clause 5.2.7 of 3GPP TS 29.122 \[6\].

Table 8.1.7-1: Supported Features

<col style="width: 16%" />
<col style="width: 23%" />

</colgroup>

<th>Feature Name</th>
<th>Description</th>
</tr>

<tr class="odd">
<td>1</td>
<td>SEALDDSupport</td>
<td><p>This feature indicates the support of the SEALDD functionality related enhancements.</p>
<p>The following functionalities are supported:</p>
<p>- Support the EAS capability for seamless transport layer service continuity within the EAS profile.</p></td>
</tr>
<tr class="even">
<td>2</td>
<td>EdgeApp_2</td>
<td><p>This feature indicates the support of the first set of enhancements to the Edge Applications functionalities.</p>
<p>The following functionalities are supported:</p>
<p>- Support of the indication of the general context holding time.</p>
<p>- Support of the EAS bundle functionality.</p>
<p>- Support of the indication of the EAS ability to handle bundled EAS ACRs within the EAS profile.</p>
<p>- Support of allowed MNO information in the EAS Profile.</p>
<p>- Support the provisioning of the indication on EAS support for content synchronization.</p></td>
</tr>

<td>EdgeApp_3</td>

<p>- Support multiple allowed PLMNs for an EAS.</p>
<p>- Support the further EAS status values and a new encoding for it.</p></td>
</tr>

<td>4</td>
<td>MetaverseApp</td>
<td><p>This feature indicates the support of the first set of enhancements to the Edge Applications functionalities to support metaverse applications.</p>
<p>The following sub-functionalities are supported:</p>
<p>- Support of associated devices required along with the UE.</p></td>
