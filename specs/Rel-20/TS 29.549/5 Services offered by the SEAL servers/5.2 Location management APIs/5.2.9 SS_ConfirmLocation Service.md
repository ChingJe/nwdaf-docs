# 5.2.9 SS_ConfirmLocation Service


## 5.2.9.1 Service Description

The SS_ConfirmLocation service exposed by the LM Server enables a service consumer to:

\- create/update/delete a Location Confirmation Service Subscription; and

\- receive location confirmation service usage related event(s) reporting.

## 5.2.9.2 Service Operations


### 5.2.9.2.1 Introduction

The service operations defined for the SS_ConfirmLocation service are shown in table 5.2.9.2.1-1.

Table 5.2.9.2.1-1: SS_ConfirmLocation Service Operations

| Service Operation Name       | Description                                                                                                             | Initiated by     |
|------------------------------|-------------------------------------------------------------------------------------------------------------------------|------------------|
| SS_ConfirmLocation_Subscribe | This service operation enables a service consumer to create/update/delete a Location Confirmation Service Subscription. | e.g., VAL Server |
| SS_ConfirmLocation_Notify    | This service operation enables the LM Server to notify on location confirmation service usage related event(s).         | LM Server        |

### 5.2.9.2.2 SS_ConfirmLocation_Subscribe


#### 5.2.9.2.2.1 General

This service operation is used by a service consumer to request the creation of a Location Confirmation Service Subscription at the LM Server.

The following procedures are supported by the "SS_ConfirmLocation_Subscribe" service operation:

\- Location Confirmation Service Subscription Creation.

\- Location Confirmation Service Subscription Update.

\- Location Confirmation Service Subscription Deletion.

#### 5.2.9.2.2.2 Location Confirmation Service Subscription Creation

This procedure is used by a service consumer to request the LM Server to create a Location Confirmation Service Subscription (see also clause 9.3.23 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the creation of a Location Confirmation Service Subscription, the service consumer shall send an HTTP POST request to the LM Server targeting the "Location Confirmation Service Subscriptions" collection resource, with the request body including the LocConfirmSubsc data structure.

2a. Upon success, the LM Server shall respond with an HTTP "201 Created" status code with the response body containing a representation of the created "Individual Location Confirmation Service Subscription" resource within the LocConfirmSubsc data structure.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.5.7.

#### 5.2.9.2.2.3 Location Confirmation Service Subscription Update

This procedure is used by a service consumer to request the LM Server to update an existing Location Confirmation Service Subscription (see also clause 9.3.23 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the update/modification of an existing Location Confirmation Service Subscription, the service consumer shall send an HTTP PUT/PATCH request to the LM Server targeting the corresponding "Individual Location Confirmation Service Subscription" resource, with the request body including either:

\- the updated representation of the resource within the LocConfirmSubsc data structure, in case the HTTP PUT method is used; or

\- the requested modifications to the resource within the LocConfirmSubscPatch data structure, in case the HTTP PATCH method is used.

NOTE: An alternative service consumer (i.e. other than the one that requested the creation of the targeted resource) can initiate this request.

If the LM Server is not able to handle the request, it may respond with an HTTP "307 Temporary Redirect" status code or an HTTP "308 Permanent Redirect" status code including an HTTP "Location" header containing an alternative URI of the resource located in an alternative LM Server, as defined in clause 5.2.10 of 3GPP TS 29.122 \[3\].

2a. Upon success, the LM Server shall respond with either:

\- an HTTP "200 OK" status code with the response body containing a representation of the updated/modified "Individual Location Confirmation Service Subscription" resource within the LocConfirmSubsc data structure; or

\- an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP PUT/PATCH response body, as specified in clause 7.1.5.7.

#### 5.2.9.2.2.4 Location Confirmation Service Subscription Deletion

This procedure is used by a service consumer to request the LM Server to delete an existing Location Confirmation Service Subscription (see also clause 9.3.23 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the deletion of an existing Location Confirmation Service Subscription, the service consumer shall send an HTTP DELETE request to the LM Server targeting the corresponding "Individual Location Confirmation Service Subscription" resource.

NOTE: An alternative service consumer (i.e. other than the one that requested the creation/update of the targeted resource) can initiate this request.

2a. Upon success, the LM Server shall respond with an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP DELETE response body, as specified in clause 7.1.5.7.

### 5.2.9.2.3 SS_ConfirmLocation_Notify


#### 5.2.9.2.3.1 General

This service operation is used by the LM Server to notify on location confirmation service usage related event(s).

The following procedures are supported by the "SS_ConfirmLocation_Notify" service operation:

\- Location Confirmation Service Usage Notification.

#### 5.2.9.2.3.2 Location Confirmation Service Usage Notification

This procedure is used by the LM Server to notify on location confirmation service usage related event(s) (see also clause 9.3.23 of 3GPP°TS°23.434°\[2\]).

1\. In order to notify a previously subscribed service consumer on location confirmation service usage related event(s), the LM Server shall send an HTTP POST request to the service consumer with the request URI set to "{notifUri}", where the "notifUri" variable is set to the value received from the service consumer during the creation/update of the corresponding Location Confirmation Service Subscription using the procedures defined in clauses 5.2.9.2.2, and the request body including the LocConfirmUsageNotif data structure.

2a. Upon success, the service consumer shall respond to the LM Server with an HTTP "204 No Content" status code to acknowledge the reception of the notification.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.5.7.
