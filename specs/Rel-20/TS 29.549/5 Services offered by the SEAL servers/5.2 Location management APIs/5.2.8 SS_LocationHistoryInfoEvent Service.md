# 5.2.8 SS_LocationHistoryInfoEvent Service


## 5.2.8.1 Service Description

The SS_LocationHistoryInfoEvent service exposed by the LM Server enables a service consumer to:

\- create/update/delete a Location Tracing Configuration; and

\- request Location History Report(s).

## 5.2.8.2 Service Operations


### 5.2.8.2.1 Introduction

The service operations defined for the SS_LocationHistoryInfoEvent service are shown in table 5.2.8.2.1-1.

Table 5.2.8.2.1-1: SS_LocationHistoryInfoEvent Service Operations

| Service Operation Name             | Description                                                                                   | Initiated by     |
|------------------------------------|-----------------------------------------------------------------------------------------------|------------------|
| SS_LocationHistoryInfoEvent_Create | This service operation enables a service consumer to create a Location Tracing Configuration. | e.g., VAL Server |
| SS_LocationHistoryInfoEvent_Update | This service operation enables a service consumer to update a Location Tracing Configuration. | e.g., VAL Server |
| SS_LocationHistoryInfoEvent_Delete | This service operation enables a service consumer to delete a Location Tracing Configuration. | e.g., VAL Server |
| SS_LocationHistoryInfoEvent_Query  | This service operation enables a service consumer to request Location History Report(s).      | e.g., VAL Server |

### 5.2.8.2.2 SS_LocationHistoryInfoEvent_Create


#### 5.2.8.2.2.1 General

This service operation is used by a service consumer to request the creation of a Location Tracing Configuration at the LM Server.

The following procedures are supported by the "SS_LocationHistoryInfoEvent_Create" service operation:

\- Location Tracing Configuration Creation.

#### 5.2.8.2.2.2 Location Tracing Configuration Creation

This procedure is used by a service consumer to request the LM Server to create a Location Tracing Configuration (see also clause 9.3.21 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the creation of a Location Tracing Configuration, the service consumer shall send an HTTP POST request to the LM Server targeting the "Location Tracing Configurations" collection resource, with the request body including the LocTracingConfig data structure defined in clause 7.1.4.6.2.2.

2a. Upon success, the LM Server shall respond with an HTTP "201 Created" status code with the response body containing a representation of the created "Individual Location Tracing Configuration" resource within the LocTracingConfig data structure defined in clause 7.1.4.6.2.2.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.4.7.

### 5.2.8.2.3 SS_LocationHistoryInfoEvent_Update


#### 5.2.8.2.3.1 General

This service operation is used by a service consumer to request the update of an existing Location Tracing Configuration at the LM Server.

The following procedures are supported by the "SS_LocationHistoryInfoEvent_Update" service operation:

\- Location Tracing Configuration Update.

#### 5.2.8.2.3.2 Location Tracing Configuration Update

This procedure is used by a service consumer to request the LM Server to update an existing Location Tracing Configuration (see also clause 9.3.21 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the update/modification of an existing Location Tracing Configuration, the service consumer shall send an HTTP PUT/PATCH request to the LM Server targeting the corresponding "Individual Location Tracing Configuration" resource, with the request body including either:

\- the updated representation of the resource within the LocTracingConfig data structure defined in clause 7.1.4.6.2.2, in case the HTTP PUT method is used; or

\- the requested modifications to the resource within the LocTracingConfigPatch data structure defined in clause 7.1.4.6.2.3, in case the HTTP PATCH method is used.

NOTE: An alternative service consumer (i.e. other than the one that requested the creation of the targeted resource) can initiate this request.

If the LM Server is not able to handle the request, it may respond with an HTTP "307 Temporary Redirect" status code or an HTTP "308 Permanent Redirect" status code including an HTTP "Location" header containing an alternative URI of the resource located in an alternative LM Server, as defined in clause 5.2.10 of 3GPP TS 29.122 \[3\].

2a. Upon success, the LM Server shall respond with either:

\- an HTTP "200 OK" status code with the response body containing a representation of the updated/modified "Individual Location Tracing Configuration" resource within the LocTracingConfig data structure defined in clause 7.1.4.6.2.2; or

\- an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP PUT/PATCH response body, as specified in clause 7.1.4.7.

### 5.2.8.2.4 SS_LocationHistoryInfoEvent_Delete


#### 5.2.8.2.4.1 General

This service operation is used by a service consumer to request the deletion of an existing Location Tracing Configuration at the LM Server.

The following procedures are supported by the "SS_LocationHistoryInfoEvent_Delete" service operation:

\- Location Tracing Configuration Deletion.

#### 5.2.8.2.4.2 Location Tracing Configuration Deletion

This procedure is used by a service consumer to request the LM Server to delete an existing Location Tracing Configuration (see also clause 9.3.21 of 3GPP°TS°23.434°\[2\]).

1\. In order to request the deletion of an existing Location Tracing Configuration, the service consumer shall send an HTTP DELETE request to the LM Server targeting the corresponding "Individual Location Tracing Configuration" resource.

NOTE: An alternative service consumer (i.e. other than the one that requested the creation/update of the targeted resource) can initiate this request.

2a. Upon success, the LM Server shall respond with an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP DELETE response body, as specified in clause 7.1.4.7.

### 5.2.8.2.5 SS_LocationHistoryInfoEvent_Query


#### 5.2.8.2.5.1 General

This service operation is used by a service consumer to retrieve Location History Report(s) from the LM Server.

The following procedures are supported by the "SS_LocationHistoryInfoEvent_Query" service operation:

\- Location History Report(s) Retrieval.

#### 5.2.8.2.5.2 Location History Report(s) Retrieval

This procedure is used by a service consumer to request to retrieve Location History Report(s) from the LM Server (see also clause 9.3.21 of 3GPP°TS°23.434°\[2\]).

1\. In order to retrieve Location History Report(s), the service consumer shall send an HTTP GET request to the LM Server targeting the URI of the "Location History Reports" collection resource, with the request URI containing query parameter(s) to filter the responses from the LM Server.

2a. Upon success, the LM Server shall respond with an HTTP "200 OK" status code with the response body containing the requested Location History Report(s) within the LocHistoryReports data structure defined in clause 7.1.4.6.2.5.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP GET response body, as specified in clause 7.1.4.7.
