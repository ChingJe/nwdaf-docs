# 5.2.10 SS_SLPositioningManagement API


## 5.2.10.1 Service Description

The SS_SLPositioningManagement API, as defined 3GPP TS 23.434 \[2\], enables a service consumer to:

\- create/update/delete a SL Positioning Management Subscription;

\- receive SL Positioning Management related event(s) notification; and

\- request SR based positioning information.

## 5.2.10.2 Service Operations


### 5.2.10.2.1 Introduction

The service operations defined for the SS_SLPositioningManagement API are shown in the table 5.2.10.2.1-1.

Table 5.2.10.2.1-1: Service operations of the SS_SLPositioningManagement API

|                                          |                                                                                                                           |              |
|------------------------------------------|---------------------------------------------------------------------------------------------------------------------------|--------------|
| Service operation name                   | Description                                                                                                               | Initiated by |
| SS_SLPositioningManagement_Subscribe     | This service operation is used by a service consumer to to create/update/delete a SL Positioning Management Subscription. | VAL Server   |
| SS_SLPositioningManagement_Notify        | This service operation is used by the LM Server to notify on the SL Positioning Management event(s).                      | SEAL Server  |
| SS_SLPositioningManagement_SRInfoRequest | This service operation is used by a service consumer to request SR based positioning information.                         | VAL Server   |

### 5.2.10.2.2 SS_SLPositioningManagement_Subscribe


#### 5.2.10.2.2.1 General

This service operation is used by a service consumer to request the creation of a SL Positioning Management Subscription at the LM Server.

The following procedures are supported by the "SS_SLPositioningManagement_Subscribe" service operation:

\- SL Positioning Management Subscription Creation.

\- SL Positioning Management Subscription Update.

\- SL Positioning Management Subscription Deletion.

#### 5.2.10.2.2.2 SL Positioning Management Subscription Creation

This procedure is used by a service consumer to request the LM Server to create a SL Positioning Management Subscription.

1\. In order to request the creation of a SL Positioning Management Subscription, the service consumer shall send an HTTP POST request to the LM Server targeting the "SL Positioning Management Subscriptions" collection resource, with the request body including the SlPositionMgmtSubsc data structure.

2a. Upon success, the LM Server shall respond with an HTTP "201 Created" status code with the response body containing a representation of the created "Individual SL Positioning Management Subscription" resource within the SlPositionMgmtSubsc data structure.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.6.7.

#### 5.2.10.2.2.3 SL Positioning Management Subscription Update

This procedure is used by a service consumer to request the LM Server to update an existing SL Positioning Management Subscription.

1\. In order to request the update/modify an existing SL Positioning Management Subscription, the service consumer shall send an HTTP PUT/PATCH request to the LM Server targeting the corresponding "Individual SL Positioning Management Subscription" resource, with the request body including either:

\- the updated representation of the resource within the SlPositionMgmtSubsc data structure, in case the HTTP PUT method is used; or

\- the requested modifications to the resource within the SlPositionMgmtSubscPatch data structure, in case the HTTP PATCH method is used.

If the LM Server is not able to handle the request, it may respond with an HTTP "307 Temporary Redirect" status code or an HTTP "308 Permanent Redirect" status code including an HTTP "Location" header containing an alternative URI of the resource located in an alternative LM Server, as defined in clause 5.2.10 of 3GPP TS 29.122 \[3\].

2a. Upon success, the LM Server shall respond with either:

\- an HTTP "200 OK" status code with the response body containing a representation of the updated/modified "Individual SL Positioning Management Subscription" resource within the SlPositionMgmtSubsc data structure; or

\- an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP PUT/PATCH response body, as specified in clause 7.1.6.7.

#### 5.2.10.2.2.4 SL Positioning Management Subscription Deletion

This procedure is used by a service consumer to request the LM Server to delete an existing SL Positioning Management Subscription.

1\. In order to request the deletion of an existing SL Positioning Management Subscription, the service consumer shall send an HTTP DELETE request to the LM Server targeting the corresponding "Individual SL Positioning Management Subscription" resource.

2a. Upon success, the LM Server shall respond with an HTTP "204 No Content" status code.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP DELETE response body, as specified in clause 7.1.6.7.

### 5.2.10.2.3 SS_SLPositioningManagement_Notify


#### 5.2.10.2.3.1 General

This service operation is used by the LM Server to notify on SL Positioning Management related event(s).

The following procedures are supported by the "SS_SLPositioningManagement_Notify" service operation:

\- SL Positioning Management Event Notification.

#### 5.2.10.2.3.2 SL Positioning Management Event Notification

This procedure is used by the LM Server to notify on SL Positioning Management related event(s).

1\. In order to notify a previously subscribed service consumer on SL Positioning related event(s), the LM Server shall send an HTTP POST request to the service consumer with the request URI set to "{notifUri}", where the "notifUri" variable is set to the value received from the service consumer during the creation/update of the corresponding SL Positioning Management Subscription using the procedures defined in clauses 5.2.10.2.2, and the request body including the SlPositionMgmtNotif data structure.

2a. Upon success, the service consumer shall respond to the LM Server with an HTTP "204 No Content" status code to acknowledge the reception of the notification.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.6.7.

### 5.2.10.2.4 SS_SLPositioningManagement_SRInfoRequest


#### 5.2.10.2.4.1 General

This service operation is used by a service consumer to request SR based positioning information to the LM Server.

#### 5.2.10.2.4.2 Short-Range based positioning information request

This procedure is used by a service consumer to request Short-Range based positioning information.

1\. In order to request the Short-Range based positioning information, the service consumer shall send an HTTP POST request to the LM Server with the request body including the SrPosInfoReq data structure specified in clause 7.1.6.4.

2a. Upon success, the LM Server shall respond with an HTTP "200 OK" status code with the response body containing a representation of the Short-Range based positioning information within the SrPosInfoResp data structure.

2b. On failure, the appropriate HTTP status code indicating the error shall be returned and appropriate additional error information should be returned in the HTTP POST response body, as specified in clause 7.1.6.4.
