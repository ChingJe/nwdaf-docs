# 8.38 ML model inference service performance management and feedback


## 8.38.1 General

This clause describes a client-to-AIMLE feedback mechanism for ML model inference service performance. After an ML model inference request as specified in clause 8.36 is processed, the client (VAL server, AIMLE client) evaluates the received ML model inference result against the expected service quality parameters (e.g., expected latency, accuracy, confidence), and may report a feedback message to AIMLE if late, failed, degraded, or inaccurate outcomes are detected. The AIMLE server validates and aggregates feedback together with runtime observations and can use the aggregated information to adjust subsequent discovery and selection decisions (e.g., update performance profiles or candidate ranking used in discovery responses).

Pre-condition:

\- ML model inference services have already been discovered and invoked through the AIMLE server according to procedures in clause 8.38. The client (VAL server, AIMLE client) has received ML model inference results from AIMLE.

## 8.38.2 Procedure for ML model inference service performance management and feedback

Figure 8.38.2-1 illustrates the ML model inference feedback reporting procedure.

Figure 8.38.2-1: ML model inference service performance feedback

1\. The AIMLE server sends an ML model inference service performance feedback subscription request to the VAL Server or AIMLE client to subscribe for receiving ML model inference service feedback. The request specifies the feedback scope (target ML model inference services), expected reporting types (e.g., latency, accuracy, confidence metrics or error conditions), and optional reporting frequency or threshold criteria.

2\. Upon receiving the subscription request, the client authenticates the AIMLE server and validates the subscription parameters. If authorization fails, the client rejects the subscription request with a corresponding cause value and the procedure terminates.

3\. If the request is authorized, the client sends a feedback subscription response message to the AIMLE server indicating successful establishment of the feedback subscription and any negotiated parameters (e.g., reporting scope or frequency).

4\. When the client subsequently invokes an ML model inference service and receives an ML model inference result as defined in Clause 8.36, the client locally evaluates the result against the expected service quality parameters (e.g. latency, accuracy, confidence level) that were expressed during discovery or ML model inference service request.

5\. If the client detects that the received ML model inference result is late, failed, inaccurate, or otherwise deviates from the expected QoS, it sends an ML model inference service performance feedback notification message to the AIMLE server in accordance with the previously established subscription.

6\. Upon receiving the feedback notification, AIMLE validates the message and returns an ML model inference service performance feedback notification acknowledgement message to the client, confirming successful receipt or rejecting the notify with a cause.

7\. Local AIMLE server action to updating service performance profiles and discovery policies: the AIMLE server aggregates received feedback reports and updates the service performance profile associated with the affected ML model inference services. The updated profile is used to refine future service discovery and selection decisions (e.g., candidate ranking, node prioritization, load balancing).

NOTE: A service performance profile is an AIMLE-maintained record of aggregated QoS statistics for each ML model inference service (e.g., average latency, success rate, accuracy level, availability). It is used for policy optimization and candidate selection.

## 8.38.3 Information flows


### 8.38.3.1 ML model inference service performance feedback subscription request

Table 8.38.3.1-1 describes the information flow of ML model inference service performance feedback subscription request from the AIMLE server to the AIMLE client.

Table 8.38.3.1-1: ML model inference service performance feedback subscription request

| Information element                  | Status | Description                                                                                                                                                                                                                                                                                                                                               |
|--------------------------------------|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Requestor identity                   | M      | Identity of the AIMLE server initiating the feedback subscription request.                                                                                                                                                                                                                                                                                |
| Target ML model inference service(s) | M      | Identifies the ML model inference service or set of ML model inference services (e.g. by service ID or ML model ID) for which performance feedback is being requested.                                                                                                                                                                                    |
| Feedback metric types                | M      | Indicates the performance metrics and event types on which feedback is requested (e.g. ML model inference latency, accuracy, confidence level, error conditions). At least one metric type shall be included.                                                                                                                                             |
| Reporting criteria                   | O      | Specifies optional criteria for feedback reporting, such as the frequency of reports or threshold values that trigger a notification (e.g. report only if latency exceeds a certain value). If absent, the default is that the client provides feedback for each ML model inference execution that does not meet the expected service quality parameters. |

### 8.38.3.2 ML model inference service performance feedback subscription response

Table 8.38.3.2-1 describes the information flow of the ML model inference service performance feedback subscription response from the AIMLE service consumer (client) to the AIMLE server.

Table 8.38.3.2-1: ML model inference service performance feedback subscription response

| Information element                                           | Status | Description                                                                                                                                                                                                                                                           |
|---------------------------------------------------------------|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Success response (NOTE)                                       | O      | Indicates that the ML model inference service feedback subscription request was accepted by the client. This IE is present if and only if the subscription request is accepted.                                                                                       |
| \> Feedback subscription identifier                           | M      | Identifier of the established feedback subscription (echoed from the request). The client uses this identifier in subsequent feedback notifications to refer to this subscription.                                                                                    |
| \> Accepted reporting criteria                                | O      | If the client adjusts the requested reporting frequency or thresholds, this IE specifies the finally agreed criteria for feedback notifications (e.g. a modified minimum interval between reports). If omitted, the reporting criteria remain as initially requested. |
| Failure response (NOTE)                                       | O      | Indicates that the feedback subscription request was not accepted. This IE is present if and only if the subscription is rejected by the client.                                                                                                                      |
| NOTE: Only one of these information elements shall be present |        |                                                                                                                                                                                                                                                                       |

### 8.38.3.3 ML model inference service performance feedback notification

Table8.38.3.3-1 describes the information flow of the ML model inference service performance feedback notification from the AIMLE service consumer (client) to the AIMLE server.

Table 8.38.3.3-1: ML model inference service performance feedback notification

| Information element                                           | Status | Description                                                                                                                                                                                                                                                                                                      |
|---------------------------------------------------------------|--------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Feedback subscription identifier                              | M      | Identifier of the feedback subscription context to which this notification belongs (as provided in the subscription request/response).                                                                                                                                                                           |
| ML model Inference service identifier                         | M      | Identifies the specific ML model inference service or ML model instance related to this feedback report if the subscription covers multiple ML model inference services                                                                                                                                          |
| Performance feedback type                                     | M      | Indicates the type of performance event being reported. For example, this IE can denote that the ML model inference result was late, had insufficient accuracy/confidence, or otherwise failed to meet an expected performance criterion.                                                                        |
| Observed performance metrics (NOTE)                           | O      | If the feedback is related to a performance degradation (with an ML model inference result delivered), this IE provides the relevant performance measurements observed by the client. For example, it may include the actual ML model inference latency or accuracy/confidence level associated with the result. |
| Failure cause (NOTE)                                          | O      | If the ML model inference execution failed or the result was unusable, this IE provides the reason for the failure (e.g. ML model inference timeout, model error, or other execution failure details).                                                                                                           |
| NOTE: Only one of these information elements shall be present |        |                                                                                                                                                                                                                                                                                                                  |

### 8.38.3.4 ML model inference service performance feedback notify acknowledgement

Table 8.38.3.4-1 describes the information flow of the ML model inference service performance feedback notification acknowledgement from the AIMLE server to the client.

Table 8.38.3.4-1: ML model inference service performance feedback notify acknowledgement

| Information element                                           | Status | Description                                                                                                                                                                                   |
|---------------------------------------------------------------|--------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Success acknowledgement (NOTE)                                | O      | Indicates that the AIMLE server has successfully received and processed the ML model inference service feedback notification. This IE is present if and only if the notification is accepted. |
| \> Feedback subscription identifier                           | M      | Identifier of the feedback subscription for which the notification was received (echoed from the subscription context).                                                                       |
| Failure acknowledgement (NOTE)                                | O      | Indicates that the AIMLE server failed to process the feedback notification. This IE is present if and only if the notification was rejected or not applied.                                  |
| \> Cause                                                      | M      | Reason for the failure to process the notification (e.g. unknown subscription ID, invalid message content, or other error).                                                                   |
| NOTE: Only one of these information elements shall be present |        |                                                                                                                                                                                               |
